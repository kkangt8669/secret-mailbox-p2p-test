① 두 스마트폰 설정

준비
접속 전
연결 방법: 두 스마트폰에 같은 방 번호와 PIN을 입력하고, 각각 A·B로 지정한 뒤 「연결 시작」만 누르면 됨. 긴 연결 정보 복사·붙여넣기는 필요 없음.
이 페이지는 통신 시험용임. 4자리 PIN과 공개 연결 중개 서비스를 사용하므로 실제 사적인 대화나 개인정보는 입력하지 마십시오. 공개 PeerJS 서버는 연결 협상만 맡고, 메시지는 WebRTC로 직접 전송함. TURN 중계는 설정하지 않았음.

② 메시지 시험

양쪽에서 연결 시작을 눌러보십시오.
전송 대기: 0건
연결되지 않을 때도 메시지는 이 스마트폰 브라우저에 암호문으로 저장됨. 재연결되면 자동 전송하며 상대방의 저장 확인(ACK)을 받은 후에만 대기 목록에서 제거함. 브라우저 데이터를 삭제하면 미전달 메시지가 사라질 수 있음.
연결 진단: 대기 중
연결 진단 로그 보기
준비됨
ICE 로그에는 실제 IP·mDNS 호스트명·SDP 원문을 기록하지 않음. 연결 실패 후보다 ICE checking 중 진단이 유효함. PeerJS 외부 라이브러리와 비교하려면 함께 제공된 direct_webrtc_test.html을 이용함.
A만 최초 연결을 요청하고 B는 수신에 집중함. 이번 버전은 ICE 후보의 주소 계열·mDNS·UDP/TCP와 SDP 협상 정보를 개인정보 없이 진단함. 후보가 ICE checking 중일 때 중복 요청으로 덮어쓰지 않으며, 진단 로그에 ICE 후보쌍의 검사 요청·응답 횟수를 표시함. 메시지는 로컬 보관 후 ACK를 확인함. 네트워크를 Wi-Fi ↔ LTE 전환 후 PING/PONG으로 상대방 응답을 확인함. 응답이 없으면 기존 채널을 폐기하고 자동으로 새 연결을 시도함. 백그라운드 메시지 수신은 보장하지 않음.
